# 气球雨（balloon-920）开发文档

**版本**：v2.0（模块化架构）  
**日期**：2026-06-30  
**适用范围**：`balloon-920/` 目录下全部后续开发  

本文档描述自 v1.9 单文件 HTML 解耦重构后的代码框架。**后续功能必须按本结构扩展**，避免回退到单文件或跨模块随意耦合。

---

## 1. 项目概览

| 项 | 说明 |
|----|------|
| 入口 HTML | `index.html`（仅 HTML + CSS + 一行 module 脚本） |
| 入口 JS | `js/main.js` |
| 应用核心 | `js/BalloonGameApp.js` |
| 模块规范 | ES Modules（`import` / `export`） |
| 运行方式 | 本地 HTTP 服务打开（需加载 `assets/bgm.mp3` 等资源） |

**设计原则**

1. **玩法与表现分离于结构**：重构只动架构，不改数值与视觉效果；新功能亦应先挂接点、再填逻辑。
2. **单一状态容器**：所有可变状态挂在 `BalloonGameApp` 实例（`game`）上。
3. **子系统类 + 扁平委托**：业务写在 `*Service` / `*Controller` 类中，通过 `_wireSubsystemMethods()` 挂到 `game` 供跨模块调用。
4. **常量与数据外置**：全局常量 → `config.js`；关卡静态表 → `level/levelData.js`。

## 3. 核心架构

### 3.1 分层关系

```
┌─────────────────────────────────────────────────────────┐
│  index.html + main.js          （启动层）                │
└───────────────────────────┬─────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────┐
│  BalloonGameApp                （应用层 / 状态容器）      │
│  - 持有 game 全部可变状态                                 │
│  - 组装子系统、绑定 DOM 事件、驱动 loop()                 │
└───────────────────────────┬─────────────────────────────┘
                            ▼
┌──────────┬──────────┬──────────┬──────────┬────────────┐
│ Level    │ Balloon  │ Pump     │ Physics  │ GameFlow   │ …
│ Service  │ Service  │ Service  │ Engine   │ Service    │
└──────────┴──────────┴──────────┴──────────┴────────────┘
                            ▼
┌─────────────────────────────────────────────────────────┐
│  Renderer / SfxSystem / InputController  （表现 & 输入）   │
└─────────────────────────────────────────────────────────┘
```

### 3.2 子系统约定

每个子系统是一个 **class**，构造函数接收 `game`（即 `BalloonGameApp` 实例）：

```js
export class ExampleService {
    constructor(game) {
        this.game = game;
    }

    doSomething(arg) {
        const game = this.game;
        // 读状态：game.balls、game.levelIndex …
        // 调其他系统：game.popBalloon(ball)  // 已通过 wire 挂到 game
    }
}
```

**注册新子系统（必须步骤）**

1. 在 `BalloonGameApp` 构造函数中：`this.xxx = new XxxService(this)`
2. 将 `this.xxx` 加入 `_wireSubsystemMethods()` 的 `services` 数组
3. 如需每帧更新 / 绘制，在 `loop()` 或 `Renderer.draw()` 中增加调用
4. 若模块持有独立数组状态，可同步到 `game` 上的同名引用（参考 `itemPickups`）

### 3.3 方法扁平挂载（`_wireSubsystemMethods`）

子系统 public 方法会 **自动绑定** 到 `game`：

```js
// BalloonService 内
popBalloon(ball) { … }

// 其他任意子系统内
game.popBalloon(ball);  // ✅ 推荐：与原单文件互调方式一致
this.game.balloonService.popBalloon(ball);  // ❌ 避免：破坏统一约定
```

新增方法时 **只需写在对应 class 上**，完成 wire 注册后全局可用，无需改 `BalloonGameApp` 转发代码。

### 3.4 状态与 DOM

| 类别 | 存放位置 | 示例 |
|------|----------|------|
| 可变游戏状态 | `game.*` | `balls`、`levelIndex`、`gameOutcome` |
| DOM 引用 | `game.dom.*` | `canvas`、`ctx`、`levelHudEl` |
| 常量 | `config.js` 或 `levelData.js` | `dt`、`AIR_CAPACITY`、`TUTORIAL_LEVELS` |
| 音效 API | `game.sfx.*` | `playPop`、`updatePump` |

子系统方法内统一写法：

```js
const game = this.game;
const ctx = game.dom.ctx;   // 绘制时
```

**禁止**在子模块中直接使用 `document.getElementById`（仅 `main.js` 收集 DOM）。

## 4. 主循环与调用顺序

`BalloonGameApp.loop()` 每帧执行（`appScreen === 'game'` 时才更新逻辑，暂停时只 `draw()`）：

| 顺序 | 调用 | 所属模块 |
|------|------|----------|
| 1 | `updateInflation()` | PumpService |
| 2 | `sfx.updatePump(...)` | SfxSystem |
| 3 | `updateBallLabelAnims()` | BalloonService |
| 4 | `updateComboHud()` | GameFlowService |
| 5 | `updatePhysics()` | PhysicsEngine |
| 6 | `updateImminentPops()` | BalloonService |
| 7 | `processChainPops()` | BalloonService |
| 8 | `checkLevelLose()` / `updateLoseCountdown()` | GameFlowService |
| 9 | `updateWinRevealCountdown()` | GameFlowService |
| 10 | `updateLevelTransition()` | LevelService |
| 11 | `updatePopEffects()` | BalloonService |
| 12 | `updateCelebrateEffects()` | GameFlowService |
| 13 | `updateItems(dt)` | ItemService |
| 14 | `draw()` | Renderer |

**新增每帧逻辑时**：插入到语义相近的步骤前后，并在本文档同步更新；避免在 `loop()` 外另起 `requestAnimationFrame`。

| `clearWorld` | 清场 → **挂钩** `clearLevelItems` |
| `updateLevelTransition` | 换关淡入淡出 |

### 5.2 BalloonService — 气球实体

| 方法 | 职责 |
|------|------|
| `createSoftBall` | PBD 气球创建 |

| `popBalloon` | 撑爆 → **挂钩** `onBalloonPop` |
| `processChainPops` | 同色连锁 |
| `spawnPopEffect` / `updatePopEffects` | 爆破粒子 |

### 5.3 PumpService — 气筒

| 方法 | 职责 |
|------|------|
| `updateInflation` | 按住打气、扣燃料 |
| `drawPumpDock` | 底部气筒 UI |
| `pumpSlotForBall` | 颜色 → 气筒槽位 |

### 5.4 PhysicsEngine — 物理

| 方法 | 职责 |
|------|------|
| `updatePhysics` | 重力、PBD 子步、边界 |
| `solveBallCollisions` | 球-球碰撞 |

### 5.5 GameFlowService — 流程

| 方法 | 职责 |
|------|------|
| `checkLevelWin` / `checkLevelLose` | 胜负判定 |
| `bumpComboHud` | 连击展示 |
| `drawSettlementOverlay`（经 Renderer） | 结算面板 |

### 5.6 其他

| 模块 | 职责 |
|------|------|
| `InputController` | 坐标转换、命中检测、拖拽 |
| `Renderer` | 背景、球体、特效、HUD、结算层 |
| `PauseController` | 暂停层；`Esc` / 切后台触发 |
| `ProgressStore` | `localStorage` 关卡进度 |

## 6. 关键游戏流程

### 6.1 启动

```
main.js
  → new BalloonGameApp(dom)
  → loadProgress()
  → bootstrapGame(levelIndex)   // 直接进游戏，不显示暂停层
  → loop()
```

### 6.2 关卡加载

```
loadLevelImmediate(idx)
  → clearWorld()              // 含 clearLevelItems()
  → computeBalloonFillLayout()
  → spawnBalloonsWithLayout() // 每球 onBalloonSpawn()
  → 初始化 pumpFuelRemaining
```

### 6.3 撑爆连锁

```
updateInflation()             // 气量归零
  → schedulePopIfEmpty / updateImminentPops
  → popBalloon(ball)
       → onBalloonPop()       // 道具
       → destroyBall()
       → enqueueChainNeighbors()
       → checkLevelWin/Lose()
  → processChainPops()        // 延时连锁
```

### 6.4 屏幕状态 `appScreen`

| 值 | 含义 |
|----|------|
| `'game'` | 正常游玩，逻辑与输入生效 |
| `'pause'` | 暂停层可见，逻辑冻结 |

## 7. 扩展新功能标准流程

以「新子系统」为例（道具模块已按此落地）：

### Step 1：划定职责

- 属于哪一层？（实体 / 系统 / 表现 / UI）
- 需要哪些挂钩点？（生成、撑爆、清场、每帧、绘制）

### Step 2：建目录与类

```
js/myFeature/
  ├── myFeatureTypes.js   # 常量、枚举、注册表（可选）
  ├── MyFeatureService.js # 主入口 class
  └── index.js
```

### Step 3：注册到 BalloonGameApp

```js
this.myFeature = new MyFeatureService(this);
// services 数组追加 this.myFeature
```

### Step 4：在既有流程加挂钩（最小侵入）

```js
// 示例：在 popBalloon 内
game.onBalloonPop(ball, ctx);

// 示例：在 spawnBalloonsWithLayout 内
game.onBalloonSpawn(ball, i, level);
```

挂钩调用 **保持一行**，具体逻辑全部在新模块内实现。

### Step 5：接入 loop / draw

```js
// loop
this.updateMyFeature(Config.dt);

// Renderer.draw
game.drawMyFeature(ctx);
```

### Step 6：数据外置

- 静态配置 → `levelData.js` 或模块内 `*Types.js`
- 程序生成 → 对应 `*Planner.js` / `*Table.js`

### Step 7：无配置时零影响

新模块在未配置数据时必须 **no-op**，保证与旧版行为一致。

## 8. 道具模块（后续开发范本）

道具分两类，已通过挂钩接入，**实现任务见 `js/items/TODO.js`**：

| 类型 | 类 | 触发时机 |
|------|-----|----------|
| **embedded** 关卡预设 | `ItemSpawnPlanner` | `onBalloonSpawn` → `ball.embeddedItem` |
| **drop** 爆破掉落 | `ItemDropTable` | `onBalloonPop` → `itemPickups` |

关卡数据扩展字段（约定）：

```js
{
  id: 1,
  title: '示例关',
  balloonCountFactor: 1,
  activeTeams: [0, 1],
  pump: [80, 80],
  embeddedItems: [
    { spawnIndex: 2, itemId: 'fuel_pack', meta: { amount: 20 } },
  ],
}
```

新增道具类型时：

1. 在 `ITEM_REGISTRY` 注册定义  
2. 实现 `onCollect(game, item, ctx)`  
3. 按需扩展 `ItemDropTable` 或 `ItemSpawnPlanner`  
4. **勿**在 `BalloonService.popBalloon` 内写道具业务逻辑

## 9. 编码规范

### 9.1 必须遵守

- 使用 ES Modules，相对路径导入：`import { x } from './foo.js'`（带 `.js` 后缀）
- 子系统内通过 `const game = this.game` 访问状态
- 绘制使用 `game.dom.ctx`，逻辑坐标系 360×800（`config.js`）
- 时间步长统一 `Config.dt`，勿硬编码 `1/60`
- 随机程序关使用 `game.levelSpawnRng` / `makeSeededRng(seed)` 保证可复现

### 9.2 禁止事项

| 禁止 | 原因 |
|------|------|
| 在 `index.html` 写业务 JS | 已迁移至 `js/` |
| 新建全局变量 `let balls` | 破坏单状态容器 |
| 跨模块 import 具体 Service 互调 | 应通过 `game.method()` |
| 直接修改 `releases/` 下快照 | 仅作版本参考 |
| 无挂钩地复制粘贴大块逻辑到 `BalloonGameApp` | 应下沉到对应 Service |

### 9.3 命名约定

| 类型 | 命名 |
|------|------|
| 子系统类 | `XxxService` / `XxxController` / `XxxEngine` |
| 工厂函数 | `createXxx`（如 `createSfxSystem`） |
| 关卡挂钩 | `onBalloonSpawn` / `onBalloonPop` / `clearLevelItems` |
| 每帧更新 | `updateXxx` |
| 绘制 | `drawXxx` |
